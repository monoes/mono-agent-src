## ODD THINGS

- **The export recipe in the brief is one directory short.** `git archive HEAD internal data cmd go.mod go.sum` leaves out `automations/`, which the CLI test package imports (`cmd/monoagentcli/automation_noseed_test.go`). The first CLI run stopped at "no required module provides package github.com/monoes/mono-agent/automations". I added `git archive HEAD automations | tar -x` to both `export` and `pristine` (a read-only command on the checkout) and compared that directory in the final `diff -r` too. The store package needed nothing else.
- **Baseline on the unmutated export:** `./internal/tasks/` passes in 12.2 s; the CLI selection of the brief passes in 23.8 s (about 36 s with the first compile). No failure on the pristine copy anywhere.
- **Row 10 is not flaky here, it is deterministic.** With `BEGIN` instead of `BEGIN IMMEDIATE`, 5 of 5 runs failed for every concurrency test tried, with `database is locked (5) (SQLITE_BUSY)` and `database is locked (517)` (SQLITE_BUSY_SNAPSHOT: a read-then-write transaction that finds the snapshot moved cannot upgrade, and `busy_timeout(5000)` does not help). The 18 tests that failed 5 of 5: TestSessionsInOtherProcessesNeverTakeTheSameTask, TestSeveralAgentsClaimingOneTaskAtOnceTakeItOnce, TestSeveralAgentsTakingTheNextTaskAtOnceTakeOneEach, TestSixteenAgentsClaimingOneTaskAtOnceTakeItOnce, TestSixteenAgentsTakingTheNextOfFiveTasksTakeOneEach, TestAClaimRacesTheHoldersReleaseFinishCommentAndRenewalAndTheOperatorsMove, TestClaimsAndARenewalRaceTheEndOfALease, TestTwoStoresOnOneFileTakeEachTaskOnce, TestASecondClaimWaitsForTheWriteLockAndThenSeesWhatTheFirstClaimDid, TestAddsWithOneClientIDAcrossProcessesMakeOneTask, TestConcurrentAddsWithOneClientIDMakeOneTask, TestApprovingOrArchivingOneTaskAtOnceSucceedsExactlyOnce, TestMovesAtOnceKeepEveryColumnInOrder, TestConcurrentAddsAllSucceed, TestRenewalsAtOnceNeverShortenALease, TestAWorkloadAtOnceLeavesAHistoryThatExplainsEveryTask, TestClaimsAtOnceWithTheOperatorsMoveArchiveOrApprovalLeaveTheCardAsAnOrderWould, TestTheLastSlotOfTheBoardIsGivenToOneCallerAtOnce. On the restored code the same 20 tests passed 5 of 5 times (26 s), so no flake was seen in either direction.
- **Row 4: the brief's mutant is weaker than the rule.** `if true {` removes the refusal but the stored kind is still `agent`, so the hourly limit still applies. I also ran 4b (the agent may file any valid source, so `--source chrome` would make a row the hourly limit does not count). The refusal tests kill both. The hourly-limit tests do not: TestAgentsMayAddTwentyTasksAnHour, TestOnlyAgentTasksUseUpTheHourlyLimit and the CLI TestTaskAddByAnAgentIsLimitedPerHourWhateverItsNameOrSource all passed under 4b, because the CLI test only tries `--source os`, which the CLI refuses before the store. "An agent past its limit cannot dodge it by naming a capture source" is therefore guarded only by the refusal tests (TestSourceKindMatrix, TestSourceKindRules, TestTaskAddSourceFlagReachesTheStore). Not a survivor by the row's rule; the controller may want to know.
- **Row 11 is killed by one test only**, the EXPLAIN-plan one, as the brief expected: the mutant counts the same rows, so no behavioural test can see it.
- **Rows 8 and 14 carry a `_ =` line** (`_ = orgsign.AgentContextMarker`, `_ = caller`). I wrote the mutants that way from the start: a bare edit would leave an unused import (row 8) or an unused variable (row 14), which Go refuses to compile; I did not try the bare versions. The extra line changes no behaviour.
- **Row 14 has a third covering test that was not in the selection:** `TestTaskEverySuggestedCommandNamesItsProfile` (`task_read_more_test.go:276`) runs `board` as the operator and, at its end under `CLAUDECODE`, expects the board's refusal text. I did not run it against the mutant; the row was already killed by the two board tests.
