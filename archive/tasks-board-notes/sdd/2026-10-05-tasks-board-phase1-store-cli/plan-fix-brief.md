# Plan fixes after the phase 1 build: common rules for the four plan fixers

Background. Phase 1 of the task board (the store `internal/tasks`, the CLI `monoagentcli task`) is built in the checkout /Users/morteza/Desktop/monoes/mono-agent/.claude/worktrees/feat+tasks-board (branch feat/tasks-board). Four later plans were written while it was being built; a drift check compared them with the code as built and found places where a plan says something phase 1 does not do. The findings are in `plan-drift-report.md` in this directory (one section per plan). The user will READ these plans before anyone builds from them, so a plan must be right and must read well. You fix ONE plan: the one your dispatch names, using the findings of its section of the drift report plus any extra items your dispatch lists.

## Rules

1. Edit ONLY your plan file (docs/mastermind/plans/2026-10-06-tasks-board-phase<N>-....md). Touch no other file in the checkout. You may create scratch material under `/private/tmp/claude-501/-Users-morteza-Desktop-monoes-mono-agent/54d60522-f555-44a3-802d-b3c4ca92ce82/scratchpad/` (a scratch export of the code is allowed: `git archive HEAD internal data cmd automations go.mod go.sum | tar -x -C <new folder>`, one command per call; run tests there only).
2. Check the CODE, not only the report: for each finding, read the code it names and make the plan's text say what the code does. If you disagree with a finding (the code is as the plan says), say so in your report and leave the plan.
3. Minimal edits. Fix the sentence, the code block or the step; do not rewrite sections, reorder tasks, or renumber. Where the plan holds code that must change, give the COMPLETE new code in the plan's own style and update every test, expected output and later reference that depends on it (grep your plan for each name you change; a name used in two tasks must stay consistent). A plan has no placeholders, no "similar to Task N", no TBD.
4. Every old-text anchor your edit relies on (an Edit step in the plan that quotes text of AGENTS.md, SECURITY.md, CHANGELOG.md, the spec or `ref_tasks.go`) must exist exactly once in the file it names, in the CURRENT tree. Check with grep -c. Another helper is editing AGENTS.md, SECURITY.md and ref_tasks.go right now (wording fixes in the phase 1 docs): quote only text that your own plan's anchors need, and say in the report which anchors you rely on.
5. Where the plan has a list of rulings (a "Ruling:" bullet list near its top), add one bullet for each decision you made that the user should know about, in that list's style.
6. Do not run or build the plan's work. Do not dispatch subagents.
7. Commit once at the end, with an explicit pathspec only (other sessions share this checkout): `git commit -m "docs(tasks): <what> in the phase <N> plan" -m "Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>" -- <the plan path>`. If git says the index is locked, wait a few seconds and retry; never delete lock files; never `git add -A`, `git commit -a`, stash, reset, rebase or amend.
8. Report: write a short report to `plan-fix-<N>-report.md` in this directory (what you changed per finding, with the line numbers in the new plan; findings you did not take and why; anchors relied on; checks you ran). Return only: the commit SHA, the number of findings fixed / not taken, and any concern.
