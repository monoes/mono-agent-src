# Review of the P3 plan (desktop Tasks tab)

Plan: `docs/mastermind/plans/2026-10-06-tasks-board-phase3-gui.md` (5,240 lines, Tasks 0-13). Line numbers below are that file's.

### Verdict

**Needs fixes.** No blocker; nothing stops an executor. Two decisions belong to the user (Questions 1 and 2). The plan is unusually concrete: the ghost drag, the keyboard map, optimistic moves with rollback, skeleton, error, empty and read-only states, FLIP and reduced motion are coded in full, not described.

Verified against the repo and clean: every anchor the plan edits exists with the quoted text; the 4 Go files and 36 of 44 js/jsx blocks parse (the other 8 are partial Sidebar and App edit snippets); no new identifier collides with package `main`; the locale JSON has 124 keys per language with the same key set and placeholders, and every `tasks.*` key the code uses exists; every CSS variable, `tb-` class and lucide icon it uses exists; no hook trap (no `sk-` run, no `task-` file name, no invisible character, no four-digit escape); the tests of Tasks 1-11 trace through their code with no failing assertion; P1 as committed and as planned matches Task 0's list (`sourceKindFor` refuses `app` from an agent, so Task 0 step 13 is right; `board --done-limit`, `Watch`, `Rev`, `Counts` as planned, P1 plan L3721-3760, L1856-1873).

The fixes below are mostly polish and test gaps. Four have real-user cost: F1 (the Done pulse is cut off), F2 (a pasted paragraph silently loses its tail), F6 (one-click approve of text never seen) and F7 (the badge can freeze on the wrong profile at startup).

### Critical and Important findings

No Critical finding.

**F1. Important: the Done check pulse, and every `justDone`/`entering` mark, ends at the next board.** Where: Task 4 `transitions` (L1661-1677), Task 10 `trans` (L4612-4615), `Card` (L2763, L2818), CSS (L3108, L3149, L3179). What: the marks are derived from the last two boards only. A Review-to-Done click renders the optimistic board (the pulse starts), and 150-300 ms later the confirming read replaces it. `transitions(optimistic, server)` finds the card already in Done, so `justDone` turns false: the class goes and the `tb-done-pop` span unmounts at about a third of the 900 ms glow and half of the 520 ms pop. Why: it is one of the four motions the brief names; it would look like a flicker; no test covers it. Fix: keep the marks in page state keyed by id with their own expiry (a ref `Map<id, expiresAt>` plus a tick, or a timeout that deletes the id after `DONE_PULSE_MS` and `ENTER_MS`); `transitions` only adds ids; compute `justDone` and `entering` from that map. Add a fake-timer test: mark a card, apply a second board that already has it in Done, assert the class stays until the timer ends.

**F2. Important: QuickAdd silently drops the tail of a long single line.** Where: Task 7 `QuickAdd.submit` (L2858-2871, the choice at L2863), Ruling at L52, Drawer title input (L4002). What: a line without `\n` is sent as a title. P1 cuts a title to 200 characters, ending in `…`, and keeps nothing in the notes (`internal/tasks/clean.go:54-60` and `:79`; `deriveTitleNotes` only fills the notes from `text`). A pasted paragraph is one line, so its tail is lost with no refusal. `edit --title=` cuts the same way. Why: data loss on an ordinary paste. Fix: send `{text}` when the trimmed value has more than 120 characters (`DerivedTitleRunes`) or a newline, so the CLI keeps everything in the notes (D29); test 120 and 121; add `maxLength={200}` to the drawer title input and test it.

**F7. Important: the badge's "newer revision wins" rule compares revisions across profiles, and the first pulse can come from the wrong profile.** Where: Task 11 `keep` (L4959-4961, `cur.rev > p.rev ? cur : p`), Review Focus 3 (L67), Task 2 `TaskPulse` (L865-884). What: revisions are per-profile counters. `app.go:168-177` says the frontend can become interactive before `startup` has finished, and `IsReady` exists for that; only `OrgsPanel.jsx:246-254` polls it, and `App.jsx` does not gate `<Sidebar>` on it.
